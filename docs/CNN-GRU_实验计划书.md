## 1. 目标与定位

**研究问题**：在 CNN 前端、输入数据、训练协议与评价日期完全相同的条件下，把时序单元从 LSTM(32,64) 换成 GRU(32,64)，能否改善西昌 32 井的次日水氡背景预测？替换会如何改变残差 LOF 的候选事件与警报负担？

**边界**（不可突破）：
- 本轮只是西昌 32 井**水氡单序列**的结构替换实验，不构成申请书「水氡—水位双流体、巧家震例」目标的完成；申请书是否变更由负责人和导师决定。
- 测试段（2022-05-16 起 1451 日）曾被 v6.1 用于选型，本轮结论只能称**回顾性探索**，不得称独立前瞻验证或地震前兆发现。
- 不预设 GRU 必胜；GRU 更好、接近、更差三种结果都可报告。当前无异常真值、井位与仪器记录，**不能直接检验"异常检测更可靠"**。
- 单位未核实前，所有量值标注「原数据单位」，不标 Bq/L。

## 3. 主实验固定协议（对两模型完全一致，禁止为任何一方单独调优）

| 维度 | 固定口径 |
|---|---|
| 任务 | 历史 60 日窗口 → 预测下一日水氡；目标日及之后数据不进输入 |
| 缺测 | 不新增插值；3 个插补日原样保留；任一特征/目标非有限值时整窗丢弃 |
| 标准化 | 各通道与目标均用拟合段中位数/IQR 做 Robust 标准化，同一组参数用于两模型 |
| 时间划分 | 按目标日：前 65% 开发段（其 85% 拟合、15% 早停验证），后 35% 回顾性测试。样本数 **2228 / 404 / 1451**；拟合末日 2021-04-06，验证首日 2021-04-07，测试首日 2022-05-16 |
| CNN 前端 | Conv1d(9→64,k3,pad1)+ReLU+MaxPool(2) → Conv1d(64→32,k3,pad1)+ReLU+MaxPool(2)，输出约 [B,15,32] |
| 唯一差异 | 单层单向 LSTM(32,64) vs 单层单向 GRU(32,64)，均取最后时间步；参数量差异属被研究的结构差异，不调宽度抵消 |
| 回归头 | Dropout 0.4 → Linear(64,32) → ReLU → Linear(32,1)；预测反标准化到原尺度后算指标 |
| 训练 | Adam lr=4.501e-4；HuberLoss(delta=1.0，作用于标准化目标)；CosineAnnealingLR；batch 128；≤200 epoch；patience 15；早停只看验证段，恢复最佳权重 |
| 随机性 | 5 个配对种子 **42,43,44,45,46**；每次**模型初始化前**重置种子；同种子两模型用同一数据窗口与同一批次洗牌序列，各自独立训练 |
| 记录 | 每次训练记录环境、参数量、最佳 epoch、实际 epoch、验证损失曲线、训练耗时 |

若 GRU 在此固定协议下不佳，只说明"在该协议下未获益"，不得推广到所有 GRU 配置；各自最佳性能的比较需另立双方同预算实验。

## 4. 执行步骤与验收门槛

**总规则**：新代码和结果只写入本工作区；旧仓库与原始数据只读。每步报告"做了什么、文件路径、核查结果、未通过项"，**未过门槛即停**，不自行改数据、划分或评价口径追分。

### 步骤 0｜盘点并冻结输入
- 复核 7 个文件 SHA-256、依赖版本、CPU 信息与命令入口 → `results/controlled_gru/manifest.json`。
- 复核 4143 日、起止、3 个插补日；核对参照预测的 1451 日与端点。
- **验收**：哈希全部吻合、日期单调无重复；单位依据缺失记入待解决项（数值比较仍可进行，量值暂标"原数据单位"）。

### 步骤 1｜最小迁移，建共用模型入口
- 迁移旧仓 `src/common.py`、`src/features/build.py`、`src/models/cnn_lstm.py`、`src/models/evaluate.py`、`src/anomaly/lof_detect.py`、`src/anomaly/events.py`、`run_v62.py` 的必要部分与 `configs/exp_v62.json`，记录来源路径与哈希；路径改指向本目录 `data/`（气象/目录读 `data/context/`，井位为空时不算震中距）。
- 模型入口加 `lstm`/`gru` 开关：共用 CNN、64 维隐藏输出与回归头；训练函数共用，仅补最佳 epoch、逐 epoch 验证损失、实际 epoch 的记录。两模型每次初始化前设种子，保留相同批次洗牌。
- **验收**：从新目录运行不依赖旧路径；两模型对同一小批输入输出 `[batch]` 且有限；旧仓库零修改；本步不看任何测试成绩。

### 步骤 2｜核对样本与旧 LSTM 复现
- 断言：9 通道顺序、目标日严格晚于输入末日、标准化只拟合拟合段、三段目标日不交叉、样本数 2228/404/1451、三个分界日期、昨日值基线与两模型测试日期一致。
- 用 seed=42 **仅训 LSTM**，测试 `date`/`y_true` 与参照预测逐项相同；与 v6.2 指标差 **MAE/RMSE ≤ 0.005、R² ≤ 0.01**（工程复现门槛，非统计等效）。
- **验收**：完全一致 + 近似复现；否则停下出差异表，由负责人决定是否以新跑 LSTM 为共同基线（旧指标不得与新 GRU 排名）。

### 步骤 3｜锁定协议，5 组配对训练（本轮核心）
- 首个 GRU 测试预测产生前，把协议、5 种子、评价脚本版本、判定规则写入 manifest；输出文件命名含模型与种子，**禁止覆盖**。
- 每种子独立训练 LSTM 与 GRU（共 10 次）；逐次保存配置、最佳权重或其哈希、最佳 epoch、验证损失曲线、`date/y_true/y_pred`、耗时；失败的种子也占一行，不许只留成功运行。
- 不因已看到某测试年/震例结果而改任何超参；共性实现错误修复后**双方五组全部重跑**，另立实验编号。
- **验收**：10 次训练记录完整、同种子两模型测试目标日与真实值逐项相同、预测有限。
- 预计耗时：CPU（torch 2.13.0+cpu）单次约 5–15 分钟，10 次约 1–3 小时，后台批量执行。

### 步骤 4｜预测评价与简明不确定性
- 每种子同测试日算 MAE（首要）、RMSE、R²（整体+逐年）、平均偏差；与同日昨日值基线比较；全部反标准化后计算。
- 输出逐种子 `GRU−LSTM` MAE 差、五种子均值/范围、逐年差值；可对同日配对损失差做预设 60 日连续块重抽样 1000 次的描述性区间（不构成显著性检验）。
- **验收**：汇总表可从逐日 CSV 复算；无日期错位、无把标准化尺度当物理单位。

### 步骤 5｜同口径残差 LOF 与震例核查
- 每模型/种子用同一测试日的 `y_true−y_pred`，复用：7 日残差窗特征、`k_strategy(role="residual")`（1451 日 → k=25）、30 窗口留出块、相邻 6 窗口排除（embargo=6）、间隔 ≤3 日事件聚合、分位数集合 0.90/0.95/0.98/0.985/0.987/0.99/0.995、展示分位 q=0.98、90 日警报覆盖率。
- 各模型对自身分数取 q=0.98 仅为历史展示，**不能作为异常能力相等的证据**；比较事件日期、重合、持续时间与警报负担。
- 预设震例（西昌 M5.1、长宁 M6.0、宁蒗 M5.5、芦山 M6.1、泸定 M6.8/M5.6、巧家 Ms5.1）照旧报告完整窗口/未检出/不可评估；井位缺失 → 命中/误报记"不可评估"，不填零；不得事后调阈值凑单例"命中"。
- **验收**：LOF 输入与参数一致、得分日期一致；不以异常窗数或单例选模型。

### 步骤 6｜交付报告与图件
- 交付：`manifest.json`、10 次完整训练记录、每种子预测/指标/LOF 结果、总比较表、图件、`results/controlled_gru/report.md`（中文；先列通过门槛，再列失败与缺失）。

## 6. 评价、筛选规则与结论边界

**首要指标**：同日配对 MAE（原数据单位）。同时报告 RMSE、整体与逐年 R²、平均偏差、五种子均值与范围。1451 个测试日窗口高度重叠，不当作独立显著性重复。

**预先登记的内部筛选门槛**（项目组管理判断）：五种子平均测试 MAE 比新跑 LSTM **降低 ≥5%**；**≥4/5** 配对种子改善；**任一测试年份**五种子平均 MAE 不得比 LSTM 高出 5% 以上；两模型都与同日昨日值比较。全部满足仅可写「GRU 值得后续独立验证」，不得直接改称正式主模型；未满足或不完整 → 保留 CNN-LSTM 并如实报告。LOF 仅描述性比较，不作胜负裁判。RF/LSTM/LSTM-RF 既有基线地位保留，本轮不重跑。

**结论边界**：不写"已证明 GRU 优于 LSTM"、不写"已发现地震前兆"；LOF 自参照得分用完整测试段，不构成可实时运行预警系统；结构变化不能保证预测无先行信号的首次突变。
